# Account access (0.4.29)

Account in the top bar replaces manual inference API configuration. Sign in/create an AI credit account using email or Google in the system browser, approve the displayed code, then return to KAI. The same verified account, wallet balances and model catalog are used by the website. GPT OSS 120B is the default for new sign-ins and previously empty model selections. The Account model dropdown preserves an existing saved choice and displays unavailable models as disabled. The selected model's free-credit eligibility and input/output pricing appear below the dropdown. Leave Credit source on Automatic · connected accounts, or choose a specific connected wallet, then enable "Use purchased credits" to authorize paid inference. Free-only remains the default. Automatic mode uses the website primary credit account first, then another linked account that can cover the request. The balance shown belongs to the primary or first connected account; it is not a pooled total. Chats, tasks and automatic memory extraction use that choice.

Credits are not token counts: the UI shows free and purchased credit units and the service's input/output price per million model tokens. Model availability is server supplied. Signed-in sessions persist in SQLCipher/Keystore storage; credentials and pending link secrets are removed from exports and diagnostic reports. Import never restores a session. Sign-out stops foreground inference and removes the local credential before attempting remote revocation. Expired sessions require sign-in again. Existing manual provider keys are retained encrypted for migration but are no longer used or editable through inference settings.

The account is for inference/billing only. Chat, memory, tasks and Composio connections remain device-local and are not synchronized or erased by changing the billing account. The Account screen explains this. Composio and optional web-search credentials are separate integrations.

KOIN Vault connection and purchases open the credit dashboard in the browser. Use the same email as the app. The wallet separately approves payments. On return, the app refreshes credits. Existing website purchases are available by choosing their linked wallet. KOIN Vault's button is enabled only when the service advertises support. The app checks the account service at runtime for Vault support and catalog context metadata; the release does not modify or deploy that service. No live payments or real-account sign-ins are performed by automated tests.

Protocol: POST /auth/device/start, POST /auth/device/poll, GET /platform/api/overview?wallet=, POST /platform/api/chat, POST /auth/logout. Session tokens go only to the fixed HTTPS credit-service origin; redirects are refused. Browser URLs contain the short approval code, never a bearer/session secret. Poll state survives process restart until expiry. The model request uses the shared credit gateway's existing streamed completion format and a per-request idempotency header. It does not auto-create an API key or use a shared project credential.
